# Phase 1 Failure Scenario Register

This register defines Phase 1 failure and attack scenarios only. It does not implement attack scripts.

| Scenario ID | Threat | Precondition | Asset affected | Prevent / detect control | Conceptual failure injection | Expected observable symptoms | Expected telemetry | Investigation path | Root-cause evidence | Remediation approach | Revalidation method | Evidence to capture |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| F01 | Public storage exposure | Object store access boundary weakened | PHI object storage | Private access model, encryption, discovery tooling | Simulate public exposure of PHI object store boundary at design level | Unexpected accessibility or policy drift symptoms | Storage access logs, exposure findings | Review object-store access configuration and findings | Policy/config evidence | Restore private access and validate encryption | Confirm no public access and expected access path only | Exposure finding, fix evidence, recheck result |
| F02 | IAM over-privilege | Role exceeds intended scope | Workload and control plane | Least privilege, access review, audit logging | Conceptually widen role scope beyond intended minimum | Unexpected access success to protected operations | IAM activity logs, suspicious API usage | Review role scope and successful unauthorized actions | Role diff and audit evidence | Reduce scope and separate duties | Re-run access validation and confirm denial | Before/after access evidence |
| F03 | KMS authorization failure | App loses decrypt authorization | Database, object storage, KMS domain | KMS separation, app monitoring, infra audit logging | Conceptually remove decrypt permission from app role | Application access failures to protected data | KMS denial events, app error symptoms | Trace failed request from app to KMS audit trail | KMS denial and request correlation evidence | Restore least-privilege decrypt path | Validate app recovers and unauthorized use stays denied | Failure and recovery traces |
| F04 | Database/network exposure | Data-tier boundary weakened | Database | Private network design, segmentation, auditability | Conceptually expose database path beyond intended private tier | Unexpected reachability or policy exception | Network telemetry, config findings | Review connectivity path, boundary controls, drift evidence | Network/control configuration evidence | Reinstate private-only access path | Validate only approved application path remains | Exposure validation and fix evidence |
| F05 | WAF control failure | Edge rule set ineffective or bypassed | Patient/Admin API edge | WAF, app validation, monitoring | Conceptually disable or weaken WAF protection | Suspicious requests reach deeper than expected | WAF logs, edge logs, app telemetry | Compare blocked vs passed requests and app behavior | WAF rule/config evidence | Restore/tune WAF and app-side checks | Re-test scenario and confirm desired handling | WAF findings and revalidation |
| F06 | Audit logging failure | Infra or app logging disabled or incomplete | Security/audit plane | Mandatory app + infra logging, config detection | Conceptually disable a logging path | Missing or partial audit trail | Missing log alerts, config drift, telemetry gaps | Determine which plane lost visibility and when | Logging config, drift evidence, gap timestamps | Restore logging and strengthen guardrails | Confirm events are captured again end to end | Gap evidence, restoration evidence |
| F07 | Credential compromise | Workforce/admin or cloud credential stolen | Identity plane | MFA, least privilege, threat detection | Conceptually simulate compromised privileged credential usage | Unusual sign-ins or privileged actions | Auth logs, cloud audit logs, threat findings | Review identity events and correlated cloud activity | Sign-in and API audit evidence | Revoke, rotate, constrain access, improve controls | Validate new auth path and reduced blast radius | Identity compromise evidence and recovery proof |
| F08 | ePHI exfiltration | Attacker or app can read sensitive data | Database or PHI object storage | App authz, least privilege, detection, logging restrictions | Conceptually simulate unauthorized bulk read/export path | Large or abnormal data-access symptoms | App audit events, object access logs, threat findings | Review actor, target, request pattern, destination | Access-event evidence and supporting infra logs | Block path, tighten authz, review egress constraints | Validate normal access still works and bulk abuse is prevented/detected | Exfiltration simulation evidence |
| F09 | Mass ePHI deletion | Destructive access to primary data plus backup targeting | Database, object storage, backups | Backup isolation, deletion protection, restore testing | Conceptually simulate destructive delete plus attempted backup compromise | Data unavailability, restore demand | Delete events, backup access events, recovery telemetry | Review deletion path, backup-target actions, recovery readiness | Delete and backup event evidence | Restore from protected backup and harden controls | Perform recovery validation and confirm data return | Deletion, attempted backup compromise, restore evidence |
| F10 | Terraform/configuration drift | Out-of-band or unauthorized change | IaC / config plane | Desired-state authority, drift detection | Conceptually modify control outside approved path | Unexpected config state and control mismatch | Drift findings, audit trails, change history | Compare actual state vs approved design | Drift diff and actor evidence | Reconcile to approved state and improve process | Confirm drift cleared and controls restored | Drift evidence and validation proof |
| F11 | Insider VIP snooping | Authorized workforce user abuses access | Application tier and DB | App authz, purpose-of-use, patient audit events | Conceptually access a VIP patient without legitimate purpose | Access succeeds or is attempted outside normal pattern | Patient audit logs, workforce audit trails | Review actor role, target patient, purpose, correlation ID | App audit records with actor and target | Restrict access model, improve oversight, discipline path outside scope | Validate controls flag or block improper access | Audit-event and investigation evidence |
| F12 | IDOR / broken object-level authorization | App authz flaw | APIs, DB, object storage | Record/object authz, testing, audit logs | Conceptually alter identifiers to access another patient resource | Unauthorized object/record access possible | App access audit, validation results | Trace object access logic and authorization decision | Request/response and audit evidence | Fix authz logic and test coverage | Re-test direct object access denial | Validation and fix evidence |
| F13 | CI/CD supply-chain compromise | Build/deploy identity or source path abused | IaC / CI-CD plane | Secret protection, least privilege, change review | Conceptually misuse deployment identity or source trust path | Unapproved change path or suspicious deployment attempt | Change logs, secret access events, audit telemetry | Review source, identity, and intended target | Change/audit evidence | Revoke/rotate credentials, tighten workflow controls | Validate only approved path remains | Supply-chain investigation evidence |
| F14 | Ransomware-style encryption / destructive activity | Malicious encryption or destructive change | Data stores and backups | Backup isolation, detection, least privilege | Conceptually simulate destructive or encrypting behavior | Data becomes unavailable or corrupted | Data access anomalies, delete/update spikes, backup alerts | Review scope of destructive actions and backup integrity | Activity logs, data symptoms, backup state evidence | Recover from protected backups and reduce destructive privilege | Validate clean recovery and detection coverage | Destructive event and restore evidence |
| F15 | Public database or snapshot exposure | Snapshot or DB exposure misconfiguration | Database layer | Private DB design, backup/snapshot controls | Conceptually expose DB/snapshot beyond intended access scope | Unexpected accessibility to structured data | Exposure findings, audit logs | Inspect DB/snapshot access controls and audit history | Exposure config and event evidence | Restrict exposure and tighten snapshot controls | Confirm private-only access | Exposure and fix evidence |
| F16 | MFA/session abuse | Stolen session or weak session handling | Identity and admin plane | MFA, session governance, anomaly detection | Conceptually abuse session after MFA or weaken session boundary | Suspicious admin activity despite prior MFA | Auth logs, session anomalies, cloud/app audit | Review session issuance, reuse, and actor behavior | Session and action evidence | Tighten session controls, revoke sessions, improve monitoring | Confirm abuse path no longer succeeds | Session-abuse evidence |
| F17 | Cross-cloud credential abuse | Credential reuse or linked privilege across clouds | AWS/GCP admin and security domains | Credential separation, blast-radius isolation | Conceptually use one compromise to affect both clouds | Multi-environment suspicious actions | AWS/GCP audit logs, identity telemetry | Compare activity across both cloud boundaries | Cross-cloud event chain evidence | Separate credentials/roles further and constrain trust paths | Validate isolation and monitoring improvements | Cross-cloud investigation evidence |
